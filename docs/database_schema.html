What triggers an Audit Log?
  • Stock & Sales Uploads: Whenever a new Stock CSV is uploaded (overwriting inventory) or a Sales CSV is appended.
  • Manual Dashboard Edits: When a user edits Store Details (like Team Rank, Grade, Slabs), Brand Details, or Planogram Facing capacities via the UI.
  • Alias Mappings: When a user manually maps a new CSV store/product alias to a clean master code in the dashboard.
  • Allocation Overrides: When an administrator manually overrides or adjusts an engine allocation decision before dispatch.

Architecture Design Philosophy

1. The "Core Setup" is the Brain (Stores, Brands, Products)
These three tables act as the central brain. By storing the `csv_aliases` directly inside the Stores and Products tables, the central brain is smart enough to translate whatever messy data the POS/ERP throws at it without requiring human cleaning.

2. The "Rules" link the Brain (Planograms)
The Planograms table sits exactly in the middle of Stores and Brands. It uses a Composite Primary Key (`Store` + `Brand` + `Product Type`). This completely prevents duplicate or conflicting facing targets from ever being created.

3. Strict Flow Control (Stock, Sales, Allocations)
Because of this strict relationship design, if a user tries to upload a Stock CSV for a store that doesn't exist in the Stores table (and doesn't match a stored alias), the database will outright reject the insertion and alert the dashboard, ensuring dirty data never enters the math engine.
